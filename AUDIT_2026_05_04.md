# P-300 Aggressive 2.0 — Codebase Audit (2026-05-04)

## Critical / High Severity

- [x] **Divergent trade-close paths inflate R4 P&L** — `variant_engine._close_shadow_trade` computes raw `(exit - entry) * qty` with zero fees and zero funding, while `trades.close_perp_trade` deducts 10bp RT fees and applies funding. R4 shadow trades closed by `_close_due_shadows` overstate returns ~5-10bp/trade. Same divergence exists for trade-open paths (duplicate ID minting with TOCTOU race). (`services/variant_engine.py` vs `services/trades.py`)

- [x] **R4 BTC overnight exit_dt computed incorrectly** — When `exit_hour < entry_hour` (e.g., entry 20:00, exit 04:00), `entry_dt.replace(hour=exit_hour)` produces an exit_dt earlier than entry_dt (same calendar day, lower hour). Only the ETH cross-day path adds `timedelta(days=1)`. BTC overnight R4 windows get immediately closed on the next tick at whatever the current price is. (`services/variant_engine.py:290`)

- [x] **CPR ignores funding on 15-day holds — inflates LONG P&L ~75bp/trade** — Comment says "CPR holds are intraday so funding is negligible" but `TIME_STOP_DAYS = 15`. With `apply_funding=False`, at ~5bp/day average BTC funding over 15 days, that's ~75bp of unaccounted cost per trade. Estimated cumulative inflation: ~9% on historical BTC CPR trades. (`services/cpr_service.py:275-277`)

- [x] **CPI date 2025-10-24 is almost certainly wrong** — The BLS-published CPI release date for October 2025 is 2025-10-14, not 10-24. Causes CPI proximity filters (used by S-096 V4 Thu Bear) to fire on the wrong day. (`fetch_events.py`)

- [x] **ADX standalone backtest missing funding rates — inflates returns 5-20%** — Uses spot-only pricing but the live `adx_service.py` applies `apply_funding=True` on perpetual futures. During high-funding regimes (exactly when ADX LONG trades fire), funding erodes 1-5%/month. (`tools/bitstamp_adx_backtest.py`)

- [x] **Bootstrap Sharpe CI lacks bias correction — understates uncertainty** — Uses raw percentile bootstrap without BCa correction. Crypto daily returns are heavily skewed (fat left tail). The reported CI `[0.96, 2.44]` is likely too narrow on the downside — the true 95% lower bound could be 15-25% lower. (`tools/tools_statistical_validation.py:124-142`)

- [x] **FOMC service hardcoded DB path bypasses db.py** — `try_fire_for_variant` constructs a manual path to `trader.db` instead of using `db.TRADER_DB`. During replay/backtest with a monkeypatched DB, reads from the wrong database. If the observer row is missing, line 468 crashes with `TypeError`. (`services/fomc_service.py:460`)

- [x] **Lookahead canary only covers Core J+ (50%), not tactical sleeves (50%)** — The dual-clock test is excellent for `jplus.simulate` but the 6 tactical sleeves (ADX, Carry, Thu Bear, PDO, CPR, FOMC) each have their own data loaders and signal computation. None are subjected to a lookahead test. (`tests/test_jplus_lookahead.py`)

## Medium Severity

- [x] **`mild_bull` weights sum to 0.90, `bear` to 0.30 — silent capital drag** — J+ is 50% of the portfolio. In `mild_bull`, 10% of J+ capital is idle (deflates returns ~5%). In `bear`, 70% is cash. May be intentional but undocumented and inconsistent with other modes summing to 1.0. (`jplus/simulate.py:120-127`)

- [x] **Carry same-day re-entry burns unnecessary fees** — Exit sweep runs BEFORE `already_acted_today` check and does NOT set the flag. If exit closes a trade and entry condition is also true the same UTC day, a new carry trade opens immediately — burning 20bp in fees. (`services/carry_service.py:214-227`)

- [x] **Log-return vs simple-return mismatch in BTC correlation** — Portfolio returns are simple returns; BTC returns are log returns. Pearson correlation between these two types systematically understates the correlation on volatile days. (`tools/tools_statistical_validation.py:192-199`)

- [x] **PDO sleeve_name mismatch — "PDO" vs "PDO_RETOUCH"** — `_close_pdo_shadow` passes `sleeve_name="PDO"` but all other references use `"PDO_RETOUCH"`. Close-side logs and any accounting keyed on sleeve_name will be misattributed. (`services/pdo_retouch_service.py:229`)

- [x] **Polymarket probabilities not normalized — inflates expected cuts** — `E[cuts] = sum(i * P(i))` assumes probabilities sum to 1.0, but prediction market prices typically sum to ~1.10 due to vig. Systematically inflates expected cuts, potentially flipping FOMC decisions. (`services/polymarket_service.py:148-165`)

- [x] **SJ-ID overflow at SJ-10000 breaks SQLite text ordering** — `:04d` format produces 5-digit IDs past 9999. `ORDER BY id DESC LIMIT 1` returns `SJ-9999` instead of `SJ-10000`, causing a PRIMARY KEY collision. (`services/trades.py:60`)

- [x] **Missing date overlap handling in combine_replay** — Uses union of core and tactical dates. For non-overlapping periods, the missing source defaults to 0%, effectively halving that source's contribution. Deflates combined returns. (`tools/combine_replay.py:144-153`)

- [x] **Max drawdown computed on closed trades only** — Equity changes only when trades close. A trade at -40% intrabar that recovers to -5% at close is invisible. Systematically understates true MDD. (`tools/bitstamp_adx_backtest.py:303-310`)

- [x] **`cd_spot_binance` missing from health.py freshness check** — The regime classifier depends on this table but `check_trader_tables()` doesn't monitor its staleness. (`health.py:133-141`)

- [x] **Funding boundary inclusion — inclusive timestamps may over/under-count** — `WHERE timestamp >= ? AND timestamp <= ?` includes both boundaries. If a trade is entered exactly at a settlement timestamp, that settlement is included. (~3-5bp error per trade). (`services/funding.py:113-116`)

- [x] **Fed funds rate change gap — -40bp cuts misclassified as "hold"** — The range `-50 < bp <= -30` falls through to "hold" instead of "cut_50" or "cut_25". (`services/polymarket_service.py:196-206`)

- [x] **R4 leverage stacking — up to 7.5x effective leverage undocumented** — R4 returns multiplied by 2.5x (ungated), then entire 1x return multiplied by vol-target leverage (up to 3.0x). Max effective: `0.15 * 2.5 * 3.0 = 7.5x`. (`jplus/simulate.py:102-134`)

- [x] **`spot_peak` initialization to `bc[50]` instead of `max(bc[:51])`** — Misses higher values in `bc[0:50]`. Carried-forward peak could be too low, causing missed drawdown protection for 1-few days after warmup ends. (`jplus/regime.py:114`, `jplus/simulate.py:68`)
